## 🤖 GEO收录查询系统开发 SOP (提示词与任务书)## 📋 任务概述
你需要开发一个 GEO（生成式引擎优化）关键词收录与引用监控系统。系统采用“API 联网直连 + 无头浏览器自动化”的混合架构，用于批量查询目标关键词在各大主流大模型（如 ChatGPT、DeepSeek、Perplexity、文心一言等）网页端和 API 端呈现的品牌曝光度、引文链接和收录情况。
------------------------------
## 🛠 阶段一：技术选型与开发环境初始化## 1.1 技术栈指定

* 后端核心：Python 3.11+ / FastAPI（异步高并发）。
* 任务调度与队列：Celery + Redis（处理批量关键词查询排队）。
* 自动化引擎：Playwright（支持 Asyncio，内置隐藏浏览器指纹功能）。
* 存储引擎：PostgreSQL（存储关键词、报告、得分）+ Elasticsearch（用于存储 AI 回答原文并支持快速检索）。

## 1.2 智能体行动指令

   1. 初始化项目目录结构，配置 pyproject.toml 或 requirements.txt。
   2. 安装依赖：fastapi, uvicorn, playwright, openai, celery, redis, pydantic。
   3. 执行 playwright install 安装 Chromium 浏览器内核。

------------------------------
## ⚙️ 阶段二：大模型适配层开发（混合架构）## 2.1 模块 A：官方 API 直连通道（开启联网模式）
目标：调用支持联网的标准大模型 API，获取结构化文本。

* 接入列表：OpenAI (GPT-4o 联网模式)、DeepSeek-V3 API、文心一言 API（开启 enable_search）。
* 智能体编写要求：
* 构建统一的 LLMClient 抽象类。
   * 实现各平台的异步调用方法（async def call_llm(prompt: str)）。
   * 核心硬性要求：必须在 API 请求参数中显式开启“联网搜索/Web Search”插件参数。

## 2.2 模块 B：浏览器自动化通道（针对 AI 搜索/网页端）
目标：针对 Perplexity、秘塔 AI 等原生 AI 搜索引擎，通过无头浏览器模拟真实操作。

* 智能体编写要求：
* 使用 playwright.async_api 编写一个通用的网页对话提取器。
   * 反爬防护：配置 playwright-stealth 隐藏无头浏览器特征；引入动态用户代理（User-Agent）。
   * 核心逻辑：
   1. 启动 Chromium，导航至目标 AI 搜索网址。
      2. 定位输入框，使用随机延迟模拟人工键入提示词，回车发送。
      3. 异步等待 AI 文本渲染完成（等待特定的 DOM 节点或停止打字的状态码）。
      4. 关键抓取：提取回答主体中的 <a> 标签和下方的“参考信源/Citations”卡片列表，捕获引用链接（URL）与标题。
   
------------------------------
## 🧠 阶段三：GEO 核心解析与评分引擎开发## 3.1 文本与引文解析器（Parser）

* 匹配规则：
1. 正向提及：使用不区分大小写的正则或语义嵌入，检查 AI 回答主体中是否包含目标品牌词/关键词。
   2. 链接收录（GEO核心）：解析大模型引用的 URL 列表，核对是否包含用户的目标域名。

## 3.2 评分算法（Score Engine）
实现一个综合评分函数 calculate_geo_score()，基于以下权重计算该词在单个模型上的 GEO 得分（满分 100）：

* 链接引用权重（50分）：若参考信源直接引用了目标域名，得 50 分。
* 关键词提及（30分）：AI 回答中每提及一次目标关键词得 10 分，上限 30 分。
* 首屏首位度（20分）：若引文链接排在参考资料的第一位，或回答在第一段推荐，得 20 分。

------------------------------
## 🔄 阶段四：异步任务流与数据持久化## 4.1 任务调度设计

* 智能体编写要求：
1. 编写 Celery 异步任务 async_check_keyword_task(keyword_id, model_name)。
   2. 当用户提交批量关键词时，系统将任务拆分为 关键词 ✕ 模型 的多个子任务，推入 Redis 队列并行消费。
   3. 每个浏览器自动化任务限制并发数（如 Max 3），防止本地服务器内存溢出或被目标平台高频封禁。

## 4.2 数据库设计 (Pydantic / SQLModel)
设计三个核心表结构：

* Keywords：存储待查词、监测频率。
* SearchTasks：存储单次查询状态（排队中、执行中、已完成、失败原因）。
* GEORepults：存储 AI 回答纯文本快照、被引用的具体 URL 列表、最终 GEO 得分及时间戳。

------------------------------
## 🚀 阶段五：系统集成与 API 接口交付## 5.1 交付接口列表 (FastAPI)

* POST /api/v1/keywords/submit：批量提交关键词检测任务。
* GET /api/v1/tasks/{task_id}/status：查询任务进度与队列状态。
* GET /api/v1/reports/{keyword_id}：获取该关键词在各个大模型上的收录对比报表（包含引用详情和得分走势）。
